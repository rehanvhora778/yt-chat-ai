# Deployment Guide — Vercel + Render

Everything in the repo is already configured. This document is the list of
things **you** have to do by hand, in order, because they involve accounts and
secrets that cannot live in git.

Budget about **45 minutes** the first time.

---

## Architecture

```
Browser
   |
   +--------------> Vercel  (frontend/ — React + Vite, static files)
   |                   |
   |                   |  HTTPS + CORS, VITE_API_BASE_URL
   |                   v
   +--------------> Render  (backend/ — Flask + gunicorn)
                       |
                       +--> MongoDB Atlas   users, videos, chats, quizzes, OTPs
                       +--> Groq API        chat, summaries, Whisper transcription
                       +--> Gemini API      embeddings (optional)
                       +--> Gmail SMTP      signup OTP emails
                       +--> local disk      FAISS vector indexes  (ephemeral!)
```

## What is already committed for you

| File | What it does |
| --- | --- |
| `render.yaml` | Render Blueprint — creates the web service and prompts for every secret |
| `backend/gunicorn.conf.py` | Production WSGI settings (1 worker + 4 threads, 300s timeout) |
| `backend/.python-version` | Pins Python 3.11.9 — 3.13 cannot install `faiss-cpu` |
| `frontend/vercel.json` | SPA rewrites (deep links stop 404-ing), cache + security headers |
| `backend/config.py` | Refuses to boot in production with a missing DB/LLM key or a placeholder secret |

# Manual steps

## 1. MongoDB Atlas — the database

1. Sign up at <https://www.mongodb.com/cloud/atlas/register>.
2. **Create a free M0 cluster.** Pick a region close to Render's `oregon`
   (e.g. `AWS / us-west-2`) — cross-region round trips make every page slower.
3. **Database Access -> Add New Database User.** Username + password, role
   *Read and write to any database*. Save the password somewhere.
4. **Network Access -> Add IP Address -> Allow access from anywhere
   (`0.0.0.0/0`).** Render's free plan has no fixed outbound IP, so an
   allow-list of specific addresses will simply lock your own API out.
5. **Database -> Connect -> Drivers** and copy the connection string:

   ```
   mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

   Replace `<username>` and `<password>` with the real values.
   If the password contains `@ : / ? # [ ] %`, percent-encode it
   (`@` -> `%40`, `#` -> `%23`, `/` -> `%2F`) or the URI will not parse.

**Keep this string — it is `MONGO_URI`.**

## 2. Groq API key — the LLM

1. <https://console.groq.com/keys> -> **Create API Key**, copy it (shown once).
2. Check <https://console.groq.com/docs/models> that `openai/gpt-oss-120b` and
   `openai/gpt-oss-20b` are still listed. Groq retires models regularly; if
   either is gone, pick a current one and change `GROQ_MODEL` /
   `GROQ_FALLBACK_MODEL` on Render.

**Keep this — it is `GROQ_API_KEY`.**

## 3. Google Gemini API key — embeddings (optional but recommended)

1. <https://aistudio.google.com/app/apikey> -> **Create API key**.

Without it, embeddings are computed on the Render instance with `fastembed`.
That works, but it downloads a ~130 MB model on first use and eats RAM you do
not have much of on the free plan — so set it if you can.

**Keep this — it is `GOOGLE_API_KEY`.**

## 4. Gmail App Password — signup emails

Registration emails a 6-digit code and creates **nothing** until it is
verified, so **without this nobody can sign up**.

1. Enable **2-Step Verification** on your Google account.
2. Go to <https://myaccount.google.com/apppasswords>, create an app password,
   copy the 16 characters (remove the spaces).
3. Your normal Gmail password will **not** work and must never be used here.

**Keep this — it is `SMTP_PASSWORD`; `SMTP_USER` is your Gmail address.**

## 5. Deploy the backend on Render

1. <https://dashboard.render.com> -> sign in with GitHub.
2. **New + -> Blueprint** -> select the `yt-chat-ai` repo -> **Connect**.
   Render finds `render.yaml` and shows one service, `yt-chat-genai-api`.
3. It now prompts for each secret. Fill in:

   | Variable | Value |
   | --- | --- |
   | `MONGO_URI` | the Atlas string from step 1 |
   | `GROQ_API_KEY` | from step 2 |
   | `GOOGLE_API_KEY` | from step 3 (or leave blank) |
   | `SMTP_USER` | your Gmail address |
   | `SMTP_PASSWORD` | the 16-character app password from step 4 |
   | `SMTP_FROM` | same Gmail address |
   | `CORS_ORIGINS` | `http://localhost:5173` **for now** — fixed in step 7 |
   | `CORS_ORIGIN_REGEX` | leave blank |
   | `WEBSHARE_PROXY_USERNAME` / `_PASSWORD` / `YOUTUBE_PROXY_URL` | leave blank |

   `SECRET_KEY` and `JWT_SECRET` are generated by Render — do not touch them.

4. **Apply / Create Resources.** The first build takes **5–10 minutes**
   (`faiss-cpu` and `fastembed` are large).
5. Copy the service URL, e.g. `https://yt-chat-genai-api.onrender.com`.
6. Verify it is alive — open `https://<your-service>.onrender.com/api/health`.
   You should get:

   ```json
   { "status": "ok", "provider": "groq", "model": "openai/gpt-oss-120b" }
   ```

   If the deploy failed instead, open **Logs**. The app prints exactly which
   variable is missing and stops, rather than starting up broken.

**Keep this URL — it is `VITE_API_BASE_URL`.**

## 6. Deploy the frontend on Vercel

1. <https://vercel.com/new> -> sign in with GitHub -> **Import** the same repo.
2. **Root Directory -> Edit -> `frontend`.** This is the one setting people
   miss; without it the build fails because there is no `package.json` at the
   repo root. Framework, build command and output directory are read from
   `frontend/vercel.json`.
3. **Environment Variables** -> add:

   | Name | Value |
   | --- | --- |
   | `VITE_API_BASE_URL` | `https://yt-chat-genai-api.onrender.com` |

   Origin only — **no trailing slash, and do not add `/api`** (the client
   appends it). Apply it to Production, Preview and Development.
4. **Deploy**, then copy the production URL, e.g.
   `https://yt-chat-ai.vercel.app`.

> Vite bakes `VITE_API_BASE_URL` into the JavaScript at build time. Changing it
> later requires a **redeploy**, not just a save.

## 7. Point CORS at the real frontend — do not skip

Back in Render -> your service -> **Environment**:

* Set `CORS_ORIGINS` to your Vercel URL, e.g. `https://yt-chat-ai.vercel.app`
  (no trailing slash, no path).
* Optional — to let Vercel *preview* deployments call the API too, set
  `CORS_ORIGIN_REGEX` to `^https://yt-chat-ai-[a-z0-9-]+\.vercel\.app$`,
  matching your own project name.

Save. Render redeploys automatically. Until you do this, every request from
the deployed site is blocked by the browser and the UI looks broken, with a
CORS error in the console.

## 8. Verify the live app

1. Open the Vercel URL. **The first load takes ~50 seconds** — the free Render
   instance is asleep and waking up. This is normal, and the app pings the API
   on page load to start that wake-up early.
2. Register an account -> check your inbox for the 6-digit code -> verify.
3. Process a YouTube video **that has captions**.
4. Ask a question about it; try Summary, Key Points and a Quiz.
5. Export a chat to PDF.

# Free-tier limits you should know about

These are real constraints, not warnings to ignore. Each one has a fix.

### The backend sleeps after 15 minutes

A free Render instance stops when idle and takes ~50s to boot on the next
request. The frontend already fires a warm-up ping at page load to hide most
of it. **Fix:** Render Starter ($7/mo) never sleeps.

### Vector indexes are wiped on every redeploy — the big one

The FAISS index for each video is written to the instance's local disk, and
that disk is destroyed on every deploy and every restart. Video metadata and
chats survive in MongoDB, but **chatting with an already-processed video will
fail until that video is processed again.**

**Fix:** move to a paid instance, uncomment the `disk:` block at the bottom of
`render.yaml`, and add `FAISS_STORE_PATH=/var/data/faiss_store`.

### 512 MB of RAM

`faiss` + `langchain` + local embeddings is a tight fit, and transcribing a
long video can push it over — the instance is then OOM-killed and restarts.
Keep `GOOGLE_API_KEY` set so embeddings happen at Google rather than inside
your 512 MB, and stick to shorter videos. **Fix:** a larger instance.

### YouTube blocks cloud IP addresses

Videos that process fine on your laptop can fail on Render with *"YouTube is
blocking requests coming from this server"*. This is YouTube refusing
datacenter IP ranges, not a bug in the app.

**Fix:** a rotating **residential** proxy. Sign up at
<https://www.webshare.io>, then set `WEBSHARE_PROXY_USERNAME` and
`WEBSHARE_PROXY_PASSWORD` on Render. Any other provider works too — put its
full `http://user:pass@host:port` URL in `YOUTUBE_PROXY_URL`. Both the
transcript API and the audio downloader use it.

### Gmail sending limits

Roughly 500 messages/day. Fine for a project; move to Resend or SendGrid for
real traffic.

### One worker, on purpose

`gunicorn.conf.py` runs a single worker because in-progress video jobs are
tracked in that process's memory. Raising `WEB_CONCURRENCY` will make video
processing fail intermittently until that job state is moved into MongoDB.

# Updating the live app

Both platforms deploy on push to `main`:

```bash
git add -A
git commit -m "your change"
git push
```

Vercel rebuilds the frontend, Render rebuilds the backend. Changing an
environment variable in the Render dashboard also triggers a redeploy.

# Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| Deploy fails, log says *"Refusing to start in production without ..."* | That variable is missing in Render -> Environment. Add it. |
| Deployed frontend 404s on refresh, `/login` shows a blank page | Vercel Root Directory is not `frontend`, so `vercel.json` was never applied. |
| Browser console: *blocked by CORS policy* | `CORS_ORIGINS` on Render does not exactly match the Vercel origin. No trailing slash, `https://`, exact hostname. |
| Requests go to `https://your-app.vercel.app/api/...` | `VITE_API_BASE_URL` was not set at build time, or was set after the build. Set it, then redeploy. |
| Build fails on `faiss-cpu` / *Building wheel* | Python version is not pinned. Confirm `PYTHON_VERSION=3.11.9` in Render -> Environment. |
| Login hangs about a minute, then works | Free instance cold start. Expected. |
| *"Can't reach the database"* | Atlas Network Access is missing `0.0.0.0/0`, or the password in `MONGO_URI` is not percent-encoded. |
| No signup email arrives | `SMTP_PASSWORD` is a normal Gmail password, not an App Password. Also check spam. |
| *"YouTube is blocking requests coming from this server"* | Datacenter IP block — configure the proxy above. |
| Chat says the video needs processing again | Instance restarted and the ephemeral FAISS index was lost. Re-process, or add a persistent disk. |
